# Contributing

Thanks for your interest in project-brain. This repo is a living knowledge base: the design system, toolkits, agent playbook, prompts and project brains behind a set of shipped full-stack projects. Contributions that make it more useful for the next builder are welcome.

## What belongs here

- **Reusable knowledge** — a design rule, a component pattern, a prompt, a checklist step, a failure lesson — written so a stranger can apply it without the original context.
- **Corrections** — a rule that is wrong, stale, or contradicted by a newer shipped project. Say what replaced it and why.
- **New project brains** — a sanitized summary of a real project: what it is, the stack, the decisions that mattered, and what you would do differently.

## What does NOT belong here

- **Personal data of any kind** — no real names of private individuals, emails, phone numbers, credentials, tokens, account IDs, or private project details. Every addition is reviewed against this rule before merge; when in doubt, generalize.
- **Copied demo content** — component code is welcome when it is openly licensed and attributed; marketing copy, placeholder claims and fabricated numbers are not.
- **Opinions without evidence** — a rule earns its place by having worked (or failed) on a real project. Mark anything untested as untested.

## How to contribute

1. Fork the repo and create a branch for your change.
2. Put the change in the right folder (see the main README's map) and match the folder's existing style: short headings, plain language, one idea per section.
3. If you add a file, add or update that folder's `README.md` so the new file is listed with a one-line description.
4. Open a pull request describing what you added and where the knowledge came from (which project, which experiment, which source).

## Style rules (the house rules apply to docs too)

- Plain, direct language. No hype words, no filler openers.
- Every claim should be checkable: link the source, name the project, or give the number.
- Keep files self-contained — a reader who lands on one file should understand it without reading three others.
