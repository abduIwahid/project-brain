# Copywriting frameworks (Chase Dimond sheet, saved-references item 160)

Ten structures for content that has to land — posts, emails, landing
copy, case studies. They structure the CONTENT only; Abdul Wahid's voice rules
still govern the words (LinkedIn/public posts: no emojis, Unicode-bold
the impactful words, ➤ bullets, direct and factual, no hype openers;
product copy: English only; claims only as strong as the evidence).

1. **HPSCA** — Hook → Problem → Agitation → Solution → CTA.
   Outreach and launch emails; posts that must end in an action.
2. **Story Framework** — Story → Struggle → Turning Point → Lesson.
   Project case studies and build-in-public posts.
3. **Problem-Promise** — Problem → Pain → Promise → Proof → CTA.
   Landing pages (WhyRisk's "Know your risk. See exactly why." shape).
4. **AIDA** — Attention → Interest → Desire → Action.
   Short posts and emails; the classic default.
5. **Myth-Busting** — Hook → Myth → Truth → Example → CTA.
   Educational posts that correct a common misconception.
6. **Question Framework** — Question → Curiosity → Insight → Takeaway.
   Explainer posts (a natural fit for an XAI project: the product
   itself answers a "why" question).
7. **Problem-Education** — Problem → Why It Matters → How to Fix It.
   Study Hub / cohort-facing explainers; documentation-style posts.
8. **Before-After-Bridge** — Before → After → Bridge → CTA.
   Redesign and improvement announcements (portfolio rounds, project
   improvement program updates).
9. **Claim-Reason-Evidence** — Claim → Reason → Evidence → Action.
   His honesty doctrine in framework form: the model card, README
   claims, any number printed publicly. Never claim past the evidence.
10. **Objection Handling** — Hook → Objection → Reframe → Proof → CTA.
    Posts/emails answering the obvious pushback (e.g. "is the model
    actually validated?" — answer with the model card).

First uses in line: the WhyRisk launch post, the portfolio project
case studies (item 128), and the Summer 2027 internship outreach
emails (kickoff Feb 2027).

## Case-study headlines (vamshi.work, item 165)

Never title a case study with the process ("Redesigning X", "My
process for Y"). Title it with the outcome:

**Result + Number + Who it helped.**

The sheet's own rule, which is also ours: the numbers are examples —
always use your real ones. His real material clears the bar without
inventing anything (0.8307 AUC, every prediction explained; churn at
84% accuracy; a whole cohort using Study Hub).

## Resume bullets — Laszlo Bock XYZ formula (ezsnippet reel, saved-references item 270)

Every resume/CV bullet: **Accomplished [X], as measured by [Y], by doing [Z]** — from Google's former HR head Laszlo Bock. No vague filler ("hardworking, team player"). The Y number must be one actually measured by testing/evaluating the project (define success criteria, run evals); invented numbers get caught in interviews. Worked example: "Built a RAG chatbot" → "Raised answer accuracy from 40% to 78% on 50 test questions by adding re-ranking." Apply to Abdul Wahid's CV page, portfolio project bullets and internship applications — his real figures (WhyRisk AUC 0.8222 on 70,692 records; Churn 84% accuracy) already fit.
